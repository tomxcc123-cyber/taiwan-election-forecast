# 2026-11-05 Editorial GIS — 前端設計優化與驗收

## 目標與保留範圍

由平面資訊堆疊，調整成以政治地理 GIS 為主軸的研究型選舉預測工作台。保留 **HB-TLEF v5 Public Beta** 的原始民調、政黨票池、模型結果、情境分析、投票率及市場資料等所有後端計算。不得因介面改造改寫民調、勝率、歷史結果、行政界線或模型驗證標記。

## 視覺方向

- **編輯式層級**：上層品牌／搜尋／分享，下層九項功能導覽。研究狀態用連續文案而非重複高飽和警示。
- **政治地理主角**：地圖與五個關鍵戰場保持同屏。新增「專注地圖」控制，能讓 GIS 畫布全寬顯示並隨時復原，保留原有圖層、底圖、2D/3D、縣市／鄉鎮／村里切換。
- **數據閱讀**：摘要採穩定的字級階層、等寬數字視覺、細分隔線和低對比底色；不用顏色取代候選人及當選機率文字。
- **查找**：按 `Ctrl/⌘ + K` 或 `/` 開啟原生對話框，可輸入縣市、候選人姓名或功能名稱。採已公開的 22 縣市、候選人列表建索引；選取縣市會轉到競賽中心，保留現有 URL 情境參數。
- **來源狀態**：僅當民調快照 `checked_at` 與模型 `feed_checked_at` 一致，才展示已同步；`degraded` 明確標為部分來源受限。這是來源同步狀態，**不代表預測勝率已完成校準**。

## 可驗收項目

1. 搜尋九項功能、縣市名稱、繁簡「台／臺」與候選人姓名；無結果時顯示清晰提示。
2. 搜尋目的地保留 URL 的情境 `s` 參數，選縣市時清除舊鄉鎮定位，避免地圖進入不一致的層級。
3. 鍵盤上下箭頭切換搜尋結果、Enter 開啟、Escape 關閉，退出後還原焦點，原生 dialog 管理焦點陷阱。
4. 預設 GIS 與「專注地圖」雙向切換，關閉專注模式後關鍵戰場側欄恢復。
5. 桌面 1440px、980px、手機 390px 等測試；九項導覽應可水平捲動而不造成整頁水平溢出。
6. 新 CSS／JS 靜態資產需被複製到 Pages `dist`，不依賴 CDN 額外請求；遵循原有 CSP。
7. 偏好減少動態效果時停用新增的過渡與背板濾鏡，保留 `:focus-visible`、跳到主內容、`aria-pressed`、`aria-live` 等可用性處理。
8. GitHub Actions 同時跑純 JS 資料／路由驗證、模型產物驗證，以及現有 Chromium GIS 點選與各頁移動端溢出測試。

## 已知界線

本輪是資訊架構、前端視覺與導覽體驗調整；GIS 各層級的地形高程品質、行政邊界資料年份、2026 機率校準問題與外部民調來源缺漏都未因 CSS／導覽新增而改變。若瀏覽器支援不足，主要九項文字導覽仍為原生連結，直接頁面路由可用。
