# 候選人模型實作與使用

## 範圍

已落地原方案的資料層與最小可驗證候選人基本面模型。新引擎在 `model/`，訓練時不讀取 HTML、不引用舊網站預測作特徵或標籤。公開地圖仍由 `site/forecast.mjs` 的舊情境模型運作。兩者不混用分數與勝率。

本版新增2026登記名單查詢及候選人模型驗證頁。離線實驗可以用提供的81人名單計算逐候選人分布，但這些2026機率不進入公開網站。公眾可下載的是歷史驗證、係數與資料審計。

## 重現

在專案根目錄安裝 `requirements.txt`，執行：

```powershell
python -m model.pipeline --as-of 2026-09-07T00:00:00+00:00
python -m unittest discover -s tests -v
python scripts/build.py
node tests/model.mjs
```

預設結果位於 `.cache/candidate-model/`，包含 `candidate-research.json` 與中文實作報告。可指定 `--data`、`--roster`、`--output`、`--draws`。固定資料、時間、NumPy版本與種子可重現結果；跨平台浮點計算可能有微小差異。

歷史資料一次性由 `scripts/import_candidate_history.py` 匯入 `data/candidate-history.json`，有原始檔與資料雜湊。後續不是每次從网页自動重建資料。修正資料時建立新的可追蹤快照，不繞過雜湊檢查。

工作簿匯入是可選工具，額外需要 `openpyxl`（本次使用3.1.5），不屬於雲端每日建置依賴：

```powershell
python scripts/import_registration_roster.py <workbook.xlsx> --as-of 2026-09-07 --output <new-roster.json>
```

只讀取儲存格資料，不執行公式、巨集或文件內指令，也不修改原工作簿。按欄名解析；逐縣市對照明細與彙總、重複姓名、登記次序及來源URL。名稱有私用區字元或得票合計超過逐筆±0.05百分點容許值的歷史賽事不作訓練/測試標籤。

## 統計規格

每場賽事有實際列出的 J 名候選人，y = center(log(share))，X在賽事內中心化。以賽事等權損失與訓練折內標準化擬合 ridge；NumPy 的增廣最小平方法求解，不手寫矩陣求逆。正則化 alpha=0.1 為預先設定，另展示0.03/0.3敏感性，不用2022測試集調參。

五個特徵：前屆同名參選人得票、前屆具名主要政黨得票按當屆該黨參選人數分攤、前屆名單勝方標記、無精確同名紀錄標記、具名主要政黨標記。所有歷史取嚴格早於目標年份的資料。獨立參選人沒有共同「無黨籍基本盤」；小黨真實黨名保留，但缺歷史不能當作主要政黨補入特徵。

這不是因果模型，也不是經歷評分。前屆名單勝方不等同目前現任者，同名匹配不處理改名、補選或跨縣市履歷。新表中的簡歷先保留來源，不換成未訓練的能力係數。

零值若是0.1百分點精度的已列候選人得票，對數轉換採0.025百分點下限；缺候選人不補造一個零值。不完整名單的明顯缺票不以正規化掩蓋。通過總和容許值仍不代表完整名單已核實。

2018標籤用2014特徵訓練；2022留出測試。殘差尺度由訓練資料內按縣市留出的誤差估計；係數使用縣市群集bootstrap。全台/區域共同誤差0.15/0.10仍是公開假設，沒有足夠週期估計。這不是MCMC後驗，沒有假造R-hat或ESS診斷。模擬條件篩選的ESS指保留抽樣數，與MCMC ESS不同。

同批模擬先各場選出一人，再彙總各黨席次；多名無黨籍保持獨立參選，再按身分統計席次。`condition_on_winner` 會篩選所有賽事同一批抽樣，樣本太少則拒絕，不用強制覆寫勝方冒充條件後驗。

## 驗證界線

MAE/RMSE、90%區間覆蓋率/寬度、WIS、多類別Brier、log loss與分箱明細都針對同一候選人研究引擎和同一留出樣本。按賽事等權，Brier先對候選人求和再對賽事平均；機率評分用0.5次數平滑避免有限模擬產生log(0)。區間採分位數而非標準誤條帶。

回測條件為事後已知舊檔所列名單，名單沒有歷史公布時間，不能宣稱是提前180/90/30/7日的預報。只有一個留出週期，沒有可靠的跨週期校準證據；不用候選人列數冒充獨立樣本量。

## 名單來源

使用者提供的工作簿含22縣市、81名已登記參選人，截至2026-09-07。原始姓名、政黨、簡歷及來源定位留存。這是完成登記名單，不是最終審定合格名單。已逐縣市核對[中央社](https://www.cna.com.tw/news/aipl/202609045002.aspx)，並與[公視](https://news.pts.org.tw/article/801606)交叉比對人數/政黨；江啟臣/江啓臣、温世政/溫世政等字形差異記錄在 `data/registration-source-review.json`，不自行建立模糊身分連結。

## 後續階段

尚未實作完整動態聯合民調模型、調查机构效應估計、未表態歸屬推斷、經校準的ML組合或正式模型升級。原民調更新程序繼續執行，但舊三陣營民調不能直接當作81名候選人觀測。下一階段需要原始完整歷史結果、可辨識候選配對的民調，以及更多帶時間截點的訓練資料。
