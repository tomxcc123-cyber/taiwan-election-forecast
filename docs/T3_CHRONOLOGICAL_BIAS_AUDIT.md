# T3 非藍綠總票池：2018／2022 年代順序診斷（2026-11-02）

## 目的

檢查現行 HB-TLEF v5 的 `T3_roster_type` 先驗是否相對前屆延續，系統性高估非KMT／DPP候選人總得票；特別分析非藍綠候選人數量不同的縣市。**這不只是拿2026台北民調1%去「調校」模型**。原始聯合報資料是訪問時支持回應，T3預測選舉日有效票，分母與時間皆不同，不能直接當成模型損失函數的真實標籤。

## 完全凍結的測試配置

- 實際部署的 `model/v4_product.py` T3特徵（9個）、`alpha=0.3`、70%模型＋30%前次票池。不在看見結果後更改超參數。
- 2014訓練 → 2018評分；2014＋2018訓練 → 2022評分，每段22縣市，各縣市等權，與只使用前屆票池的基準相較。
- 前屆延續以及T3，都根據**當屆歷史登記候選人名單**做無非藍綠參選者時非藍綠票池設為0的共同處理，才進行可比性評分。該做法與2026的 `_compose_unified` 同性質，但當屆選前名單發布時點在歷史樣本仍需獨立核證。
- 指標：MAE、RMSE、有號偏差（正為高估）、高估／低估縣市數、5pp以內縣市數。分組：非藍綠候選人0、1、至少2名；實際非藍綠票池不到5%、5到20%、至少20%；另列非藍綠參選人至少2名但實際票池不到5%的異常風險組。
- 對2022屆次，以22縣市為抽樣單位做2000次固定種子的配對重抽樣（並非按候選人抽樣），給出「T3 − 前屆延續MAE」和T3偏差的**描述性90%區間**。不把單一屆選舉的縣市重抽樣誤解成跨屆可信區間。
- 每一屆22縣市逐筆誤差可見於網站 `t3-chronological-bias-audit.json`，而非只有均值。

## 特別的時間可得性與結論限制

1. 2018屆次在模型原先開發中**已經用於選T3規格**，因此它是「選擇期」而不是未觸碰的留出期。
2. 2022屆次在專案後續架構調整中也**已經多次被檢視**；本次對固定參數的2014＋2018→2022屬時間分割的開發診斷，不是獨立第三方新盲測。
3. `build_third_rows`使用當屆候選人完整名單算候選人數等註冊特徵，但無法僅靠衍生表確認「登記日前某一時點」這份名單完全可得。地方組織衍生表也尚缺逐欄歷史原始發布日核證。此點會削弱任何外推到「選前多少天」的結論；已寫入機器可讀 `strict_historical_candidate_ballot_roster_vintage_proven=false`。
4. 僅2014、2018、2022三屆，存在縣市共時衝擊與非獨立觀測。不得以2022偏差的顯著性或某個縣市結果來事後手工制定2026特例。
5. 沒有民調house-effect、未表態轉票與勝率參數不確定性的完整交叉驗證，單獨優化T3票池MAE也不能自動推出最終勝率更準確。

## 產物與部署

新增 `scripts/evaluate_t3_chronological_bias.py`、`tests/test_t3_chronological_bias.py`、`site/t3-chronological-ui.mjs` 與頁面驗證測試。建站時獨立計算研究JSON並發布至網站「模型驗證」，不修改 `model/v5_product.py` 的模型定義、預測先驗、民調likelihood或正式勝率。

正式改動的門檻保持**阻擋**：
`release_gate=blocked_until_independent_roster_and_probability_validation`。

在有真正可按歷史預測日重建的名單、明示發布時間的地方組織資料，以及多屆獨立驗證前，這份報告只作診斷而非自動修正。
